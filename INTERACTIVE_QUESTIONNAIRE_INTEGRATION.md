# Interactive Test Plan Questionnaire - Integration Complete

## Overview

The **Interactive Test Plan Questionnaire** has been successfully integrated into Stage 3 (Test Plan Generation) of the NOS QA Workflow application. This feature ensures that production-quality test plans matching official Extreme Networks standards are generated by collecting all necessary information upfront through a structured, user-friendly form.

## What Was Built

### 1. Frontend Components

#### TestPlanQuestionnaire.jsx (`frontend/src/components/stages/`)
- **5-section interactive questionnaire** with step-by-step navigation
- Ant Design components for professional UI (Steps, Form, Input, Select, Card, etc.)
- Form validation ensuring minimum required information
- Auto-save functionality for progress preservation
- Organized sections:
  - **Section 1: Basic Info** - Jira ID, feature name, release, priority, description
  - **Section 2: Topology** - Devices with roles/models/OS, connections
  - **Section 3: Technical Specs** - VLANs, NSI values, protocol parameters, tools
  - **Section 4: Behaviors** - Core functionality, negative scenarios, edge cases, resilience testing
  - **Section 5: Preferences** - Test case depth, additional sections, documentation URLs

#### Updated Stage3.jsx
- Modal integration for questionnaire popup (1000px wide)
- State management for questionnaire data (`testPlanInfo`)
- "Start Information Collection Questionnaire" button for new features
- Display collected information summary before generation
- "Edit Information" and "Clear & Restart" options
- Auto-load existing test plan info when returning to Stage 3
- Disable "Generate Test Plan" button until questionnaire completed

### 2. Backend API Endpoints

#### New Routes in `backend/src/routes/stage3.js`

**POST `/api/stage3/test-plan-info`**
- Save questionnaire data to database
- Store as JSON document with type `test_plan_info`
- Associated with workflow_id
- Returns document ID and filename

**GET `/api/stage3/test-plan-info/:workflow_id`**
- Retrieve latest questionnaire data for workflow
- Parse and return JSON
- Returns null if not found

**Updated POST `/api/stage3/generate`**
- Accept `test_plan_info` parameter (JSON string)
- Parse and pass to TestPlanGenerator agent
- Save test plan info alongside generated test plan
- Log test plan info inclusion for debugging

### 3. Test Plan Generator Agent Updates

#### Updated `backend/src/agents/testPlanGenerator.js`

**Modified `generateTestPlan(options)`**
- Added `testPlanInfo` parameter
- Pass to `buildUserPrompt` method
- Include in metadata for tracking

**Enhanced `buildUserPrompt()`**
- Inject structured test plan information section when provided
- Format collected data into clear, detailed prompt sections
- Emphasize specific values (VLANs, NSI, device models) must be used
- Include all 5 sections from questionnaire:
  1. Basic Information (Jira, feature, priority)
  2. Test Topology (devices, connections)
  3. Technical Specifications (VLANs, NSI, parameters, tools)
  4. Feature Behaviors (positive, negative, edge cases, resilience)
  5. Test Plan Preferences (depth, additional sections, config availability)
- Add critical requirements reminder to use specific values

## User Workflow

### For New Feature Test Plans:

1. **Navigate to Stage 3** (Test Plan Generation)
2. **Select "New Feature"** radio button
3. **Click "Start Information Collection Questionnaire"**
4. **Fill out 5-section form**:
   - Basic Info (minimum: Jira ID, feature name, release, priority, description)
   - Topology (minimum: 1+ devices with role/model/OS)
   - Technical Specs (minimum: primary VLAN, primary NSI)
   - Behaviors (minimum: 3+ core behaviors)
   - Preferences (optional settings)
5. **Click "Complete & Generate"** to close questionnaire
6. **Review summary card** showing collected information
7. **Click "Generate Test Plan"** to create official EXOS Functional Test Plan
8. **Review and approve** generated test plan

### For Returning to Stage 3:

- Existing test plan info automatically loaded
- Summary card displays immediately
- "Edit Information" available to modify
- "Clear & Restart" to start fresh
- Can regenerate test plan with updated information

### For Feature Enhancement (Existing Test Plan):

- Questionnaire **not required** for enhancements
- Upload existing test plan → Generate adds new test cases
- Same workflow as before

## Data Flow

### Questionnaire Data Structure:
```json
{
  "jiraId": "EXOS-39334",
  "featureName": "Fabric Attach Fallback Management VLAN",
  "targetRelease": "EXOS 33.7",
  "priority": "P1",
  "description": "Complete feature description...",
  "devices": [
    { "role": "FA Server", "model": "5720-24MXW", "os": "VOSS FE" },
    { "role": "FA Client", "model": "5520-48W", "os": "EXOS" }
  ],
  "connections": "5720:1/49 (trunk) <--> 5520:1/50 (trunk)",
  "primaryVlan": "4048",
  "primaryNsi": "15999999",
  "testVlans": "1000, 2000",
  "protocolParams": "BVLAN_Primary=4051\nSystem_ID=f4ce.4802.b084",
  "tools": ["IXIA", "Wireshark"],
  "positiveBehaviors": "1. Create fallback VLAN when ZTP active\n2. Add ports on NSI approval...",
  "negativeBehaviors": "1. NSI rejected → no forwarding\n2. ZTP disabled → no fallback...",
  "testReboots": true,
  "testProcessRestarts": true,
  "testCaseDepth": "concise",
  "includeCLIReference": true
}
```

### Database Storage:
```sql
documents table:
- id: UUID
- workflow_id: Foreign key to workflows
- stage_number: 3
- doc_type: 'test_plan_info'
- filename: 'test_plan_info_<workflow_id>_<timestamp>.json'
- filepath: Full path to JSON file
- content: JSON string of questionnaire data
```
